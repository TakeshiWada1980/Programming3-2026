3.2 Viteによるプロジェクトフォルダの作成

ここでは、Vite という ウェブアプリケーション開発用のビルドツールを使用して開発環境を構築していきます。前回まで使用していた Node.js と npm を、引き続き使用します。

  • Vite は「ビート」または「ヴィート」と読みます。

ターミナルを開いて、プロジェクトフォルダを作成したい位置 (C:\Users\xxxx\Documents\ など) に移動し、以下のコマンドを実行してください。

npx create-vite@9.2.1 react-todo-app --template react-ts --eslint --no-immediate

このコマンドを実行すると create-vite というツールによって、React アプリの開発に必要なファイルや設定、つまりテンプレートが自動的に生成されます。コマンドに指定している各オプションの意味は、次のとおりです。

  • @9.2.1 は、テンプレートを生成するツール (create-vite) のバージョンを指定しています。Vite 本体のバージョンとは異なります。

  • react-todo-app は、プロジェクトの名称 (=新規作成するプロジェクトフォルダの名前) を指定しています。

  • --template react-ts は、React と TypeScript を組み合わせた開発環境のテンプレートを指定しています。

  • --eslint は、コード品質チェックツールとして ESLint を使用する指定です。

  • --no-immediate は、テンプレートの作成後にパッケージのインストールや開発サーバの起動を自動では行なわない指定です。このあと、授業で使用するバージョンを指定してインストールします。

3.3.3 .gitignore

「.gitignore」は、Git によるバージョン管理の対象から除外するファイルやフォルダを指定するための設定ファイルです。Git の管理対象から除外されたファイルやフォルダは、基本的に GitHub にもアップロードされません。

実際に「.gitignore」の内容を確認すると、インストールしたパッケージを格納する node_modules フォルダのほか、データベースの接続情報や API キーなどの機密情報を記述する .env.local ファイルが、Git の管理対象から除外されるように設定されています。

これにより、不要なファイルや機密情報を誤って GitHub にアップロードすることを防ぐことができます。

C言語 や Python用の Linter もあります。ESLint は、特に ECMAScript (JavaScript / TypeScript) 用の 標準Linter として知られています。

import { useState } from "react";

const App = () => {
  const [count, setCount] = useState(0);
  const countUp = () => {
    const newCount = count + 1;
    setCount(newCount);
  };
  return (
    <div>
      <h1>TodoApp</h1>
      <button onClick={countUp}>count is {count}</button>
    </div>
  );
};

export default App;

3.8 Tailwind CSS の適用

この授業では、Tailwind CSS という CSS フレームワークを使用して解説を進めますが、すでに使い慣れた CSS フレームワークがあれば、そちらを使用しても問題ありません。

Tailwind CSS は、あらかじめ用意された スタイルを指定するための小さな CSS クラス を組み合わせて、UI のデザインを調整する点に特徴があります。

例えば、ボタン要素の背景色や余白、角の丸みなどを設定する場合、Tailwind CSS では、それぞれのスタイルに対応した ユーティリティクラス (特定のスタイルを適用するための CSS クラス) と呼ばれるものを組み合わせて指定します。

具体的には、次のようなユーティリティクラスが用意されています。

  • m-5：上下左右に 5 スケール分の外側余白 (マージン) を設定する
  • rounded：四隅を丸くする
  • bg-blue-500：背景色を青色 (色の濃さを表す値が 500) にする
  • px-5：左右に 5 スケール分の内側余白 (パディング) を設定する
  • py-1：上下に 1 スケール分の内側余白 (パディング) を設定する
  • text-white：文字色を白色にする

これらを以下のように適用すると…

<button className="m-5 rounded bg-blue-500 px-5 py-1 text-white">
  ボタン
</button>

次のようにボタンのスタイルを調整することができます。

Tailwind CSS を採用することで、独自の CSS クラス名を考えたり、スタイルの衝突を気にしたりする場面 が少なくなり、非常に効率的に UI を開発できます。また、デザインの一貫性や保守性を保ちやすいというメリットもあります。

なお、本科目の後半で扱う Next.js も Tailwind CSS に対応しており、さまざまな ウェブアプリの開発で利用されています。

4 ポート番号のカスタマイズ

Vite で構築したプロジェクトでは、デフォルトで 開発サーバ (npm run dev) が 5173 番ポートで起動します。このポート番号は、vite.config.ts で変更することができます。

プロジェクトフォルダの直下にある vite.config.ts を、次のように変更してください (第08行目 から 第12行目 が変更箇所です)。

import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

// https://vite.dev/config/
export default defineConfig({
  plugins: [react(), tailwindcss()],
  server: {
    port: 3000,
    strictPort: false,
    open: true,
  },
});

ターミナルから npm run dev を実行し 3000番ポート で開発サーバが起動することを確認してください。

  ➜  Local:   http://localhost:3000/

また、open: true の設定により、開発サーバーの起動時に Web ブラウザが自動的に開く ようになります。

Vite で構築した React プロジェクトを 開発モード ( npm run dev ) で実行したときに、各ファイル (各コンポーネント) が どのような順序で読み込まれ、実行されていくのかについて解説します。

ここでは、理解のしやすさを優先するため、一部の説明を簡略化しています。厳密な動作とは異なる部分があることに注意してください。

まず、ウェブブラウザがプロジェクトフォルダの直下にある index.html を読み込みます。このように、プログラムの実行や処理の開始点（起点）となるものを エントリーポイント と呼びます。

  1. index.html が読み込まれ、そこから……
  2. src/main.tsx が読み込まれ、そこで……
  3. src/App.tsx で定義された App コンポーネントが呼び出される。

さらに、今後の演習では、App コンポーネントの内部に TodoList コンポーネント（src/TodoList.tsx）を配置し、その内部に TodoItem コンポーネント（src/TodoItem.tsx）を配置していきます。

この場合、コンポーネントの階層構造はさらに深くなり、次のような流れになります。

  1. index.html が読み込まれ、そこから……
  2. src/main.tsx が読み込まれ、そこで……
  3. src/App.tsx の App コンポーネントが呼び出され、その内部で……
  4. src/TodoList.tsx の TodoList コンポーネントが呼び出され、その内部で……
  5. src/TodoItem.tsx の TodoItem コンポーネントが呼び出される。

このように、React では、コンポーネントの内部に別のコンポーネントを配置することで、画面の構成を階層的に組み立てていきます。

7.1 Reactにおけるコンポーネントとは

Reactアプリは、基本的に コンポーネント (Component) とよばれる 機能と UI を持った画面構成の部品・パーツ を組み合わせてアプリを構築する点に特徴があります。

React における「コンポーネント」とは、具体的には JSX を戻り値として返す関数など を指します。今回のプロジェクトでは、主に .tsx という拡張子を持つファイルにコンポーネントを定義していきます。

また、JSX (JavaScript XML) とは、JavaScript (TypeScript) のコードのなかに HTML に似たタグ形式の記述 を組み込めるようにした拡張構文です。

7.2 状態管理

React アプリでは、アプリ画面上で変化する値を「状態（State）」と呼ばれる仕組みで管理します。この「状態」が更新されると、React はその変更をトリガーとして、関連するコンポーネントを自動的に再レンダリング（再描画）し、画面の表示を更新します。

何らかの値（例えば「現在のカウント値」）を 状態（State） として管理し、その値の変化を画面に反映させるには、通常の変数を定義するだけでは不十分です。

React では、フック（Hook） と呼ばれる特別な仕組みを利用して、状態の保持や更新などを行います。React にはさまざまなフックが用意されていますが、その中でも 状態管理の基本となるものが useState です。

先ほどのサンプルアプリでは、カウント値が変更されたときに、その結果を自動的に画面へ反映させたいため、第04行目で useState を使用しています。

具体的には、useState(0) によって、現在のカウント値を保持する count と、その値を更新するための関数 setCount を取得しています。

const [count, setCount] = useState(0);

なお、useState の引数には 状態の初期値を指定します。例えば、カウントを「7」から開始したい場合は、const [count, setCount] = useState(7); と記述します。

  • useState(0) は、useState<number>(0) のように、状態として扱う値の型を明示的に指定することもできます。型を省略した場合は、初期値から TypeScript が型を推論します。

そして、現在のカウント値を取得するときは count を参照し、カウント値を更新するときは setCount(newCount) を呼び出します。

setCount によって状態が更新されると、React が画面の再レンダリングを行い、画面に表示されるカウント値も更新されます。

import { useState } from "react";

const App = () => {
  const [count, setCount] = useState(0); // ◀◀ 初期化(初期値を設定)
  const countUp = () => { 
    const newCount = count + 1;
    setCount(newCount); // ◀◀ 更新処理
  };
  return (
    <div className="mx-4 mt-10 max-w-2xl md:mx-auto">
      <h1 className="mb-4 text-2xl font-bold">TodoApp</h1>
      <button
        className="rounded bg-blue-500 px-4 py-2 text-white hover:bg-blue-700"
        onClick={countUp}
      >
        count is {count}
      </button>
    </div>
  );
};

export default App;

一方で、以下のように useState を使用せずに実装するとボタンを押下しても画面が更新されません (=カウント表示が変わらない)。実際に試してみてください。

  const countUp = () => {
    count++; // 通常の処理で更新 count = count + 1; でも同じ

  };
  return (
    <div className="mx-4 mt-10 max-w-2xl md:mx-auto">
      <h1 className="mb-4 text-2xl font-bold">TodoApp</h1>
      <button
        className="rounded bg-blue-500 px-4 py-2 text-white hover:bg-blue-700"
        onClick={countUp}
      >
        count is {count}
      </button>
    </div>

};

export default App;

ただし、[F12] でデベロッパーツールを起動して、コンソールタブからログを確認してみると、画面上の「カウント値」が更新されないだけで、内部的には変数 count は正常に更新されていることが確認できます。

これらのことから「変更をトリガーに再レンダリングする必要がない値」については通常の変数として扱い、逆に「値の変更をトリガーに再レンダリングしたいもの」は、useState を使って「状態」として扱う必要があることが分かると思います。

8.5 TodoListコンポーネントのブラッシュアップ

現状の src/TodoList.tsx は、todos の要素数に関わらず 固定で「3件」のTodoしか表示すること ができません。しかも、todos の要素数が 2個以下のときは実行時エラー が生じます (Todoが1個も表示されなくなります)。

上記のプログラムを次のように書き換えます。前回講義の オブジェクト型の配列に対するmapの適用 を参考にしながら、この書き換えを理解してください。

import type { Todo } from "./types";

type Props = {
  todos: Todo[];
};

const TodoList = (props: Props) => {
  const todos = props.todos;

  if (todos.length === 0) {
    return (
      <div className="text-red-500">
        現在、登録されているタスクはありません。
      </div>
    );
  }

  return (
    <div className="space-y-1">
      {todos.map((todo) => (
        <div key={todo.id}>
          {todo.name} 優先度: {todo.priority}
        </div>
      ))}
    </div>
  );
};

export default TodoList;

書き換え後のプログラムでは、todos が 空配列のとき (todos.length === 0 のとき) には、Todoリストの代わりに「現在、登録されているタスクはありません。」というメッセージを表示するようにしています。

また、map の戻り値となる一番外側の JSX 要素 (この例では <div> 要素) については、第21行目 のように 必ず key 属性を設定してください。key の値には 配列内で重複せず、同じ Todo では再レンダリングしても変わらない値 を指定します。このアプリでは、各 Todo の id を使用します。

key 属性を設定していないと、実行時に Each child in a list should have a unique "key" prop という警告が表示されます。また、再レンダリングに際して意図した動作をしなくなる可能性があります。詳しい原理は生成AIで解決してください。

前回講義で学んだように、Todoの並び替えは「配列のsortメソッド」を利用して行なうことができます。例えば、優先度を昇順 (1👉2👉3の順) にしたいときは、第08行目の const todos = props.todos; を以下のように書き換えます。
